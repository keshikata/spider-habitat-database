# 距離・標高を使う250mのローカル試作

2026-10-08。モデル `spatial-exploration-1.2.0`。Cloudflareへ未配信。

## 入力と条件

- 約10m（1/12000度）のJAXA HRLULC 2024JPN_v25.04、国土数値情報の行政区域2025年版、国土地理院DEM10mを読み取り専用で使用する。
- 元の1km版で収録した単一県のメッシュと行政区域内の画素に範囲を合わせる。県境等の除外範囲を新たに埋めたわけではない。
- 画素ごとに土地被覆、200m/800mで分けた標高帯、水域・人工構造物・海岸線・林縁・水田までの距離帯の組合せを数える。分類0は土地被覆欠損、標高帯3は標高欠損。
- 距離は100m、250m、500m以内、および500mより遠い場合を区別する。画素中心間の直線距離であり、水際の線までの厳密な距離や移動距離ではない。水域は海を含む。
- 距離変換は処理区画中央の緯度におけるWGS84のメートル換算で近似し、500mを超える周囲の画素も読む。元データの欠損・細い流路・処理地域の外側の未収録地物は誤差要因として残る。
- 「海岸の草地」は草地 AND 海岸線から指定距離以内。C23の海岸線を約10m格子へラスタ化し、距離を独立して計算する。内陸の湖や河川は海岸の距離の対象にしない。
- 「水辺の草地」は草地 AND 水域への近さ。「公園・庭」は草地・森林・竹林 AND 人工構造物への近さという代理条件。公園の境界や管理状態の同定ではない。
- 「林縁の草地」は草地 AND 林縁への近さ。林縁は森林・竹林と既知の他分類が接する画素で近似し、未分類との境界は対象にしない。「水田およびその周囲」は水田から指定距離以内の陸地、「水田の畦」は水田に近い草地で近似する。畦の幅や形状は識別できない。
- 全178環境の限定語を確認した。[対応一覧](habitat-condition-review.md)に計算条件・代理条件・不足データを記録する。河川・湖沼の種類、里山、人工林、微環境などの重要な限定条件が不足する環境は面積・地図に加算しない。計算できる環境と混在する種では、除外した環境を画面と出力に明示する。
- 一つの環境記述の条件をAND、複数の記述をORで結合する。同じ画素は二重計上しない。より広い環境の記述が併記される場合、距離を変えても面積が変わらないことがある。
- 画面上部で生息環境名と計算条件を併記し、複数選択をすべての種に共通適用する。各種に登録された環境との積集合を評価し、種の一覧も絞り込む。初期状態は全環境、すべて外した場合は未選択として面積を表示しない。選択はURLの`habitat`に保持し、比較・CSV・GeoJSONにも同じ条件を使う。
- 標高帯は元発表の仮区分を継承する。平地200m未満、低山地・丘陵200–800m未満、山地800m以上。植生帯や種の標高限界を推定した値ではない。緯度・地域差、気温は未評価。
- 標高が必要な記述では欠損を除外する。標高指定のない別の環境記述があれば、その条件では候補になり得る。

## 集計と配信

1km区画を縦横4分割した約250m区画へ、元画素の分類組合せを集計する。250m区画の中央緯度で画素面積を換算するため、旧1km集計とは小さな面積の丸め・近似差があり得る。元の分類別画素数の一致は全処理区画で検査し、不一致ではビルドを停止する。

`scripts/build_spatial.py` は約16kmのタイルへ分割し、各圧縮ファイルのハッシュとサイズを記録する。再開用のキャッシュはラスタのサイズ・更新時刻、ビルドコード、元の収録メッシュJSONの内容ハッシュで識別し、キャッシュした圧縮ファイルのハッシュも照合する（原ラスタの内容ハッシュではない）。入力を凍結・保存して再実行すること。

通常の操作は距離・標高を使う複合環境を使用し、旧URLの`model=cover`もローカル版では`elevation`へ移行する。明示的に標高を外した場合は、標高条件が未適用であることを表示する。距離を使わない基本版の計算関数は検証・比較用に保持する。

ブラウザは広域表示を使い、拡大時だけ最大24タイルを読み込み、8タイルをキャッシュする。本土・島に限定した範囲ではズーム8以上から約250m区画を使い、島の形を確認しやすくする。地図ファイルは圧縮16MB・展開32MB、地域区分ファイルは圧縮16MB・展開64MBを上限にして検証する。全国の250m区画を最初に読み込まない。

基本の計算結果は `local/spatial/`、複合環境を拡張した版は `local/spatial-compound/` に作成する。ループバックの開発サーバーが後者の `/preview-data/` の許可したファイル名だけを読み出す。`site/` のCloudflare配信対象にも、公開コードリポジトリにも含めない。

実行には追加の分析用依存 `numpy`、`scipy`、`rasterio` が必要。通常のサイト閲覧には不要。

```sh
python scripts/build_spatial.py --rasters /path/to/processed/rasters --habitat /path/to/habitat --workers 4
npm run dev
```

計算後の全件検証は `node scripts/check-spatial.mjs`。2026-10-08の1.2.0のローカル計算では、5,870,996区画・5,423,321,896画素・2,241タイルを検査した。詳細地図と広域集計の画素数は一致し、県別・条件別の面積差は浮動小数点計算による最大約0.035m²。最大詳細ファイルは圧縮351,095バイト、広域ファイルは10,106,418バイト、地域区分ファイルは14,404,322バイト。初回取得量は旧版より増えたため、疎形式を使用し、全国の詳細区画は読み込まない。生態学的な精度の検証とは別である。

## 海岸・林縁・水田からの距離を追加する計算

`scripts/build_coastal.py` はC23海岸線2006年版の39都道府県分を読み込み、旧1024層に海岸・林縁・水田の各4距離帯を加えた65536層（schema 4）を作る。集計は非ゼロの層だけを保持する疎形式。JGD2000（EPSG:4612）をWGS84へ変換し、土地被覆と同じ格子に線をラスタ化する。周囲600m相当の範囲から線を抽出し、500mを超える余白で距離変換する。線のラスタ化は通過する画素を採用するため、距離は格子幅程度の近似誤差を含む。

全2,241タイルを元画素から再計算する（うち海岸線が近いのは1,093タイル）。追加した3距離の区分を除いて畳み込んだ全区画・全条件の画素数が旧版と一致しなければ停止する。島の区分も引き継ぎ、県別・島別集計、広域・詳細地図、CSV、GeoJSONに同じ条件を使う。

```sh
python scripts/build_coastal.py --rasters /path/to/processed/rasters --coast /path/to/coast-source --workers 4
python scripts/audit_habitat_rules.py --refresh
node scripts/check-spatial.mjs
node scripts/check-record-geography.mjs
```

`coast-source/sources.json`には39個のZIPのファイル名、URL、SHA256、サイズ、取得日と利用条件を記録する。原線と加工集計は公開リポジトリへ含めない。2006年の線であり、その後の埋立て・侵食・災害による変化を反映しない。水辺に近いことと海岸に近いことを同じ条件にしない。

## 本土・離島による範囲の限定

`build_record_geography.py` は国土数値情報N03の県別陸地図形とJSCの島の代表点を照合し、各250m区画に本土・島のIDを割り当てる。県ごとの最大の連続陸地を本土とする（沖縄県は除く）。島の代表点が一つの陸地図形に入る場合だけ対応させる。記録に含まれる187島名のうち183島名を対応でき、島後・沖ノ島・海驢島・竹生島は未対応として除外・表示する。近い島への推測割り当てはしない。

区画中心が海上の場合は、その県の陸地図形と一つだけ交わる区画をその陸地へ割り当てる。複数の陸地と交わる場合は除外する。海岸線で10m画素を再切抜きした結果ではなく、250m区画による近似である。小島や運河などで分割された陸地の欠落には注意が必要。島名などの詳細が不明な県別記録がある場合は県全域を対象とし、勝手に本土へ振り分けない。

地図、面積、CSV、GeoJSONは共通の `recordScope` を使う。「全地域の環境だけで比較」は記録制限を外す。地域区分データのない土地被覆版は従来の県単位であり、画面にその旨を表示する。

```sh
python scripts/build_record_geography.py --boundaries 'zip:///path/to/N03-20250101_GML.zip!N03-20250101_prefecture.shp' --islands /path/to/JSC/dist/data/Island.json
node scripts/check-record-geography.mjs
```

追加依存は `geopandas`、`shapely`、`numpy`。出力は `local/spatial/geography.json.gz` とハッシュ等を記載した `geography-manifest.json`。元の空間タイルmanifestとSHA256を照合し、異なる版での利用を拒否する。原図形や島の区分データは一般配信に含めない。

2026-10-08の1.2.0全件検証では5,870,996区画を検査し、228陸地区分の面積・広域画素数・詳細地図の一致を確認した。旧1.0.0の距離のみの設定でのアマミキムラグモのCSV合計630.040km²はGeoJSONの10,438区画の合計630.039965km²と丸めの範囲で一致した（標高を加えた現在の初期設定とは別条件）。

## GIS出力の形式

地図の現在の表示範囲をGeoJSONで出力する。座標順は経度・緯度（CRS84）。区画のポリゴン、種名、候補画素面積、割合、条件、出典を保持する。区画全体を生息確認地や生息地境界と解釈しない。ブラウザのメモリを抑えるため大きな範囲を拒否し、出力中止にも対応する。

FeatureCollectionの `metadata.selected_habitats` は選択した環境ID・環境名・土地被覆・5種類の距離・標高条件に加え、計算可能／代理条件／未評価の区分と不足条件・近似の限界を保持する。各Featureの `habitat_ids` は明示選択したID（全環境を既定使用する場合はnull）。nullを環境なしと解釈せず、具体的な条件はCollectionのメタデータで確認する。CSVにも選択した環境名・ID・計算条件の限界を含める。

## クモ類以外への応用

環境の記述を地図の条件へ対応させる枠組みは、他の生物群にも応用を検討できる。現在の規則・距離・標高帯をそのまま別の生物群へ流用した場合の妥当性は未検証。分類・生態情報・対象環境に合わせた設定と、独立した観察データによる検証が必要。
