# 標高機能の申請・承認後の公開

2026-10-13に準備。申請送信は利用者の指示で後日とし、承認待ちのデータはローカルに保存する。公開中のサイトは標高条件を必要とする環境の計算保留を維持する。

## 利用者の操作

申請を行い、承認が届いたらこのチャットへ知らせる。承認番号・指定された表示文・対象範囲は承認書または公式の申請記録から確認し、こちらで記録・出典表示・公開を行う。申請がWeb地図のみでなく、集計JSON・CSV・GeoJSON・資料図版の掲載も対象としているかを確認する。

## 準備した仕様

- 平地側の上限と山地側の下限を100m刻みで変更する。初期値は200m・800m。上限は下限より小さくし、100mから3000mまでの有効な基準だけを受理する。
- 原DEMを100m刻みで集計し、3000m以上は一つの帯、欠損は別区分とする。負の有効標高は最下位の帯に含める。
- 文献の平地・低山地・山地という記述を、選択した標高範囲で近似する。地形分類や地域の植生帯の確定とは区別し、UIと保存結果へ限界を示す。
- 標高が必要な環境では高さの条件を必ず満たし、欠損を候補に含めない。距離・土地被覆・植生・地域条件も共通で適用する。
- 選択した基準をURL、CSV、GeoJSONへ保持する。閾値を変えた計算マスクを別に扱い、古い条件の結果を再使用しない。
- 海岸線・河川距離は今回の標高承認で解放せず、引き続き保留する。

## 承認後に行うこと

承認書をローカルに保存してSHA-256を記録する。対象URL・使用承認・許可された出力・指定表示を照合し、`verified-approval.json` を作成する。これは申請者情報を含む書類そのものではなく、人が確認した公開条件の記録。未承認・未記入・一部の出力だけの承認では公開処理を停止する。

必要なキー：`status: approved`、`authority: 国土地理院`、`article: 30`、`number`、`issuedOn`、`site`、`receiptPath`、`receiptSHA256`、`preparedManifestSHA256`、`preparedReadinessSHA256`、`outputs`、`attribution`。出力範囲は `web_map`・`spatial_json`・`csv`・`geojson`・`presentation_figures`。指定文と番号はWeb、配信データ、CSV・GeoJSON、資料の説明へ反映する。承認書と現在の準備版の版が異なる場合は、自動的に公開しない。

```sh
node scripts/release-elevation.mjs local/gsi-application/verified-approval.json
```

このコマンドで承認条件を照合し、全タイルの射影、公開フォルダの許可リスト・ハッシュ・非公開文言を検査した新規フォルダを生成する。公開を含める場合は保存した既存の公式Wranglerと配信設定を使う。追加のCLI設定を利用者に求めない。

```sh
node scripts/release-elevation.mjs local/gsi-application/verified-approval.json --deploy
```

現在の無料Cloudflare Pagesへ配信し、HTTPS・安全なヘッダー・本番ファイルの内容一致を確認する。直後にCDNの反映待ちで一致検査が失敗した場合は、配信IDと反映状況を確認してから検査だけを再実行する。申請控え・承認書・元DEMは公開フォルダへ複写しない。
