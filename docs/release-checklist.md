## 2026-10-08 コメント反映後の判断

**画面修正だけで現在の機能をそのまま一般公開できる状態にはなっていない。** 次の項目を閉じてから、公開用構成をローカルで検証する。

1. **公開データと読込経路**：現在の `loadSpatial` はlocalhostでだけ呼び出され、`local/spatial-reference/` を `/preview-data/` から取得する。`site/` をそのままアップロードすると基本の土地被覆版となり、距離・植生・離島区分・約250mのGeoJSONが現在の画面と一致しない。公開用の明示的な許可リストでデータを作り、公開URLから読み込む構成と出力を検証する。ローカルのsummaryには `dem:true` と標高帯が残るため、標高UIを外しただけでそのファイルを公開してはいけない。標高の集計軸と不要な来歴情報を除いた派生データを作り、非標高条件の面積・地図が完全一致することを検証するか、必要な利用手続の結果を反映する。
2. **加工データの配布範囲**：海岸線・河川は旧利用約款の非商用条件。[第1・3条](https://nlftp.mlit.go.jp/ksj/other/agreement_02.html)は、原データ複製物の配布、空間演算結果、GIS等のデータベースの扱いを区別している。原線を配布しないことだけで、条件別画素数の静的ファイルとCSV・GeoJSONの配布が可能とは断定しない。約250m集計・距離区分・出力項目の具体例を示して確認し、回答を記録する。出典・加工者・利用条件・近似の限界は出力にも継承する。

3. **発表資料**：現在はローカル限定の画像20枚を表示している。表紙の氏名はWeb用コピーから除去済み。資料には第三者図版と標高を用いた研究結果があるため、本文の出典整備だけでなく、図版の一般公開条件と必要な利用手続を確認してから公開用配信へ含める。

国土地理院の申請は未送信・承認未取得。DEMを含む公開を進める場合は[測量成果の利用手続](https://www.gsi.go.jp/LAW/2930-index.html)に従って再開する。標高を完全に除いた公開候補は、使用する他の素材ごとの条件を別に確認する。

分割パックの最大19,281,577バイトは[Cloudflare Pagesの1ファイル25MiB上限](https://developers.cloudflare.com/pages/platform/limits/)以内だが、現行ローカルパックを公開してよい根拠にはならない。公開用データを作成した後にファイル数・個人情報・サイズ・性能・配信ヘッダーを再検査する。

コメント対応済み：土地被覆の個別オン／オフ、「発表資料」見出しの削除（資料20枚は維持）、サイトと出力の加工者表記から氏名削除、評価方法欄の撤去、更新履歴を初回リリースの紹介へ整理。更新履歴に仮の公開日は表示せず、実際の公開時に確定する。

## 無料公開までの進め方（2026-10-08）

Cloudflare Pages Freeと既存の `spider-habitat-atlas.pages.dev` を使い、計算は手元のPC、検索・集計はブラウザーで行う。公開時に必要なのは静的ファイルで、Functions・外部DB・有料ストレージ・独自ドメインを構成に加えない。[静的ファイルへのリクエストは無料・回数無制限](https://developers.cloudflare.com/pages/functions/pricing/)。回線費・PCの運用費を除き、現行プラン内なら月額ホスティング費を0円にできる。

容量の実測：現行manifestが参照する距離・植生・地域データ2,358ファイル、520,981,252バイト（約497MiB）。別途、site全体83ファイル・約36MiB、発表画像20枚・約3.7MiB。最大ファイルは19,281,577バイト（約18.4MiB）。公開用再生成前の参考値だが、[Freeの20,000ファイル・1ファイル25MiB](https://developers.cloudflare.com/pages/platform/limits/)に収まる規模。全国データを初回に一括ダウンロードする設計にはしない。既存の地域・表示範囲別読込を維持する。

作業順序：

1. **公開専用データの生成**：研究用原本を残し、出力先を `output/public-site/` とする。許可したファイル・項目だけで組み立てる。初版は現在の非標高条件を使い、標高の集計軸を合算して取り除く。氏名・PC内パス・原DEM・元GIS・研究用CSV・申請記録は含めない。集計・地図・CSV・GeoJSONが現在の非標高結果と一致することを確かめる。これは準備できる技術作業であり、配布許諾の取得とは別である。
2. **読込経路の切替**：公開時は `/data/spatial/` と `/slides/`、研究用プレビューは既存の `/preview-data/` と `/preview-slides/` を使う設定へ変更する。ホスト名によって距離版が消える分岐をなくす。データ未配置時は明示的なエラーにし、基本の土地被覆版へ黙って切り替えない。マニフェスト・ハッシュ・サイズ検証、同一配信元、CSPを維持する。
3. **海岸線・河川の配布確認**：[公式の問い合わせ先](https://nlftp.mlit.go.jp/ksj/inquiry.html)へ、条件別画素数JSONの配信とCSV・GeoJSON保存を区別してメールで確認する。公式ページは返信が必要な場合メールを案内しており、意見フォームは返信対象外。無料閲覧の予定だけでは再配布の条件を判断できない。返答前に公開しない。問い合わせ案はローカルに準備済み・未送信。
4. **発表資料の公開用コピーを整える**：資料は残す。ページごとに自作図・外部図版・DEMを用いた結果を特定する。外部図版は公開利用が認められる条件を記録し、確認できない図は自作の説明図へ置き換えるか許諾を得る。出典を書くだけで転載可能とは判断しない。DEM由来図の挿入図としての利用と、地図データの一般配信は分けて[国土地理院の手続案内](https://www.gsi.go.jp/LAW/2930-index.html)で確認する。申請不要の例もあるため、すべてに承認が必要とは断定しない。
5. **公開構成の検証と配信**：公開専用フォルダだけを静的サーバーで開き、ネットワーク要求が研究用URLに向かないこと、スマートフォン表示、計算・保存結果、個人情報・出典、容量を検査する。その後、確認した条件を反映してWranglerで配信する。[管理画面のドラッグ＆ドロップは1,000ファイル、Wranglerは20,000ファイル](https://developers.cloudflare.com/pages/get-started/direct-upload/)なので、今回の規模ではWranglerを使う。公開後にHTTPS・ヘッダー・キャッシュを確認する。

JAXA・行政区域・植生図など、利用条件を確認済みの素材は出典・加工・ライセンス表示を整える。すべての素材へ一律に許諾申請する方針ではない。国土地理院の既存申請の再開、問い合わせの送信、実際のサイト配信は別途の実行指示を受けて進める。
