# 入力データと公開データの境界

ブラウザへ配信するデータと、ローカルで処理する研究資料を分ける。研究資料は公開リポジトリに含めない。

## 入力

`scripts/sync_jsc.py` はJapan Spider Catalogの公開サイトから、分類・分布記録・更新履歴の3ファイルをローカルへ取得する。辞書圧縮された表を復元し、種・亜種の分類と県別の記録件数に変換する。配信元の写真・人物・備考・座標は出力しない。

生息環境の入力CSVは `Scientific Name` と `habitat_text` の列を持つ。利用権限のある資料を用意し、元の図鑑記述をそのまま配信しない。

環境集計は9地域のJSONを入力する。`version: 3`、`grid: "third_order"`、`aggregation: "all_source_pixel_centers_by_prefecture"`。`cells` は `[第3次メッシュコード, [[県番号, 16分類の画素数]]]` の配列で、県境重複のない単一県の区画を対象とする。画素格子は1/12000度。分類コード0は未分類、1〜15は公開ページに示したJAXAの分類に対応する。異なる版・格子・分類のデータへ無検証で差し替えない。

研究資料の学名対応は `site/data/taxonomy-crosswalk.json` の `rows` に置く。各行は `sourceName`、`status`、`catalogName`、`catalogId`、`acceptedName`、`relation`、`note`、`evidence` を持つ。`status: "mapped"` の場合だけ統合し、元資料の種概念を確認する。対応が不要な新しい入力だけを使う場合は `{"rows": []}` から始められる。WSC由来の対応情報には所定の出典と利用条件を付す。

## 出力

`build_data.py` は `site/data/catalog.json` と地域JSONを作る。`pack_maps.py` は検索用の軽量データと47県の詳細地図、8×8区画をまとめた広域地図をgzipで作る。面積は県・分類別の元集計を使用し、粗視化した地図から再計算しない。

地図のmanifestは圧縮ファイル名、SHA-256、圧縮前後のサイズ、区画数、範囲を記録する。ファイル名にはハッシュの先頭12文字を含む。ブラウザはサイズ上限とハッシュを検証し、必要な県だけを取得する。

## 再現性の確認

同じ入力とコード版で再構築し、`npm run check` で、元の地域JSONと圧縮版の全区画・全分類の一致を調べる。分類と県別記録を更新する場合は、取得日・出典・入力ハッシュ・更新履歴も合わせて更新する。計算の一致は、モデルの生態学的な予測精度を保証するものではない。
